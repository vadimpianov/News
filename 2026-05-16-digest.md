## Выводы

### Что применить в работе дизайнера

1. **"Harness" для Claude Code + Figma** — если используете Claude Code с Figma MCP, создайте набор Skills-ограничений для каждого уровня: токены, компоненты, layout. Без этого AI будет генерировать hex вместо токенов и новые компоненты вместо библиотечных. (Sen Lin, UX Collective)

2. **Claude Design для идеации, Figma для production** — оптимальный подход: Claude Design для быстрых черновиков и концептов (особенно на встречах), Figma для финализации, коллаборации и handoff. Не заменяйте одно другим. (Lenny's Newsletter)

3. **shadcn/ui как benchmark** — если ваша дизайн-система не учитывает shadcn/ui, AI-инструменты (включая Claude) всё равно будут генерировать его паттерны. Лучше знать своего конкурента. (Pawel Klasa)

4. **"Structure First, Screens Second"** — в эпоху AI-генерации, ценность дизайнера смещается от визуального исполнения к системному мышлению. Работайте как "городские планировщики", а не "художники". (Nayyerabbas)

5. **NotebookLM + Claude Design** — связка для product-дизайнеров: research synthesis в NotebookLM → визуальные артефакты в Claude Design. Один pipeline от исследования до презентации.

6. ⭐ **ЗАПОМНИТЬ — Harness-подход Sen Lin:** Создание 4 Skills для контроля качества генерации в Figma — конкретный, реализуемый метод. Решает главную боль: AI мощный, но без правил генерирует мусор. Это фреймворк, который можно внедрить прямо сейчас.

7. ⭐ **ЗАПОМНИТЬ — shadcn/ui как "скрытый стандарт":** 114K+ звёзд, паттерны проникли в AI-генерацию. Если вы не изучили shadcn/ui — изучите. Ваши AI-прототипы уже его используют.
