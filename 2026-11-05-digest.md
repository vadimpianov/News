## Выводы

### Что применить в работе дизайнера

1. **Мигрировать дизайн-системы из standalone Claude Design до 14 декабря.** Это срочная задача для всех, кто использует claude.ai/design. После этой даты — только read-only.

2. **Использовать Claude Design внутри обычных чатов и Claude Code** — больше не нужно переключаться на отдельный сайт. Команда `/design-sync` синхронизирует дизайн-систему.

3. **Писать Claude Skills для борьбы с «AI-шным» видом** — японский подход: задать строгие правила (тон, типографика, спейсинг, компоненты) в skills-файле. Это превращает generic вывод Claude в результат, соответствующий бренду.

4. **MCP + dev-mode CSS для точности** — при работе с Figma через MCP добавлять CSS-спеки из dev-mode к промпту. Это значительно повышает точность генерации кода.

5. **Claude Design для стейкхолдер-презентаций** — прототипы генерируются как рабочий HTML/CSS/JS, поэтому стейкхолдеры взаимодействуют с настоящим интерфейсом, а не с картинкой.

6. ⭐ **ЗАПОМНИТЬ — Claude Skill для конкурентного анализа**: подход «сначала изучи конкурентов, потом генерируй» (Design with context) — это методика, которая даёт значительно более релевантный результат, чем абстрактные промпты. Практический приём: создать skill, который парсит 3–5 конкурентных сайтов и использует их паттерны как контекст для генерации.

7. ⭐ **ЗАПОМНИТЬ — Skills-файл как design system guard**: вместо того чтобы полагаться на промпты, зафиксировать правила дизайн-системы в файле skills. Claude будет проверять каждый вывод по этим правилам автоматически. Это масштабируемый подход к consistency.
