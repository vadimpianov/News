## Выводы

### Приёмы, которые можно применить в работе

1. **Трёхуровневый AI-воркфлоу дизайнера:**
   - Exploration → Claude Artifacts (быстрый PoC за 10 минут)
   - Build → Claude Design (полные прототипы с дизайн-системой)
   - Precision → Claude Code + Figma MCP (production-quality код)

2. **Codebase-first дизайн-система:** Подключить theme.json / style-dictionary токены к Claude через MCP — инструмент мгновенно адаптирует border-radii, тени, типографику. Не начинать с пустого листа.

3. **Handoff bundle вместо спецификаций:** Claude Design упаковывает дизайн, intent и контекст в единый пакет для Claude Code. Это сокращает потери при передаче дизайн→код.

4. **Claude Skills для «не-AI-шного» дизайна:** Использовать markdown-инструкции (Skills) с точными стилями, палитрами и типографикой — это предотвращает генерацию «generic AI UI».

5. **Двунаправленный Figma-воркфлоу:** Дизайн в Figma → MCP → код → обратно в Figma. Позволяет дизайнерам ревьюить и итерировать прототипы в привычной среде.

### Ключевые инсайты

- **Промпт — это новый скилл дизайнера.** Дизайнеры, которые научились переводить дизайн-мышление в «intent-rich language», получают лучшие результаты.
- **Claude Design — не замена Figma, а upstream-инструмент.** Для идеации и быстрых прототипов — Claude, для продакшн-макетов и пиксельного контроля — Figma.
- **Лимиты использования — реальная проблема.** 2 промпта могут съесть 95% недельного лимита на Pro. Нужно планировать промпты и максимально использовать итерации внутри одного проекта.

### ⭐ ЗАПОМНИТЬ

**Codebase awareness — главный дифференциатор Claude Design.** В отличие от v0, Figma Make и Canva AI, Claude Design может подключиться к GitHub-репозиторию через MCP и извлечь реальную дизайн-систему (токены, компоненты, паттерны). Это означает, что генерируемые прототипы используют **настоящие** стили и компоненты проекта, а не generic AI-дизайн. Для команд с established codebase это кардинально меняет качество прототипов и сокращает gap между дизайном и продакшном.
