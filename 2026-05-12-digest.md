## Выводы: что можно применить в работе дизайнера

### 1. Дизайн-система до промпта — обязательна
Настройте токены (exact hex, exact font names, pixel spacing) в Claude Design или в `claude.md` до начала генерации. 15–20 минут инвестиций = разница между профессиональным и "AI-шаблонным" результатом.

### 2. Anti-pattern инструкции работают
Прописывайте запреты явно: "no card grids", "no hero sections", "no stock photo placeholders". Layout-level generics наносят больше вреда, чем component-level — терракотовая кнопка на стандартном hero-section всё равно выглядит как AI.

### 3. Claude Design → Claude Code = 6-минутный цикл
Для быстрого прототипирования и тестирования идей этот pipeline работает. Но для production-качества необходима ручная доводка accessibility, семантики и keyboard navigation.

### 4. Figma остаётся центром
Claude Design не заменяет Figma — он дополняет. Используйте Anima или Code to Canvas для передачи результатов в Figma. Начинайте проекты в Claude Design для exploration, переходите в Figma для refinement.

### 5. Токен-бюджет — реальное ограничение
Планируйте использование Claude Design с учётом лимитов. Настройка дизайн-системы дорогая. Лучшая стратегия: один раз настроить систему, потом переиспользовать.

### ⭐ ЗАПОМНИТЬ: Неявные токены — корень "AI-эстетики"
Если не указать явные дизайн-токены, Claude генерирует свои дефолтные. Именно эти "implicit tokens" создают одинаковый AI-look. Решение: формализуйте ВСЕ дизайн-решения до генерации — цвета, шрифты, отступы, радиусы, тени, а также явные запреты на нежелательные паттерны. Это ключевой принцип для любого дизайнера, работающего с AI-инструментами.
