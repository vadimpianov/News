## 1. Компоненты & Паттерны

**Принцип:** При использовании Claude Design для композиций с дизайн-системой всегда направляй промпт на конкретный компонент, а не на целую страницу — иначе ИИ генерирует визуально похожие, но не настоящие компоненты системы.

**Почему:** Lenny's Newsletter подтвердил: Claude Design читает дизайн-систему корректно только при промптах «про систему», но при составлении страниц из компонентов перестаёт уважать исходные компоненты и создаёт lookalikes. Работа по частям сохраняет целостность системы.

**Источник:** [What Claude Design is actually good for](https://www.lennysnewsletter.com/p/what-claude-design-is-actually-good)

**Дата:** 2026-05-08

## 2. Figma-техники

**Принцип:** Инвертируй точку входа Figma: используй Claude Code для прототипирования и сбора фидбека, а Figma подключай как финальный этап для полировки и документирования, а не как стартовую точку.

**Почему:** Опыт дизайн-команды Mercari за месяц работы с Claude Code to Figma показал: когда прототип сначала живёт в коде и собирает реальный фидбек, итоговый Figma-файл получается точнее и содержит меньше правок. Традиционный порядок (Figma → код) удлиняет цикл на этапе, где точность ещё не нужна.

**Источник:** [Claude Code to Figma — месяц спустя (Mercari Design Blog)](https://note.com/mercari_design/n/nce7249cf6ed1)

**Дата:** 2026-05-08

## 3. Spacing & Layout

**Принцип:** При генерации UI через Claude Design используй кастомные слайдеры (adjustment knobs) для spacing и layout вместо текстовых промптов — это даёт предсказуемый и гранулярный контроль над отступами.

**Почему:** Claude Design генерирует кастомные ползунки для tweaking spacing, color и layout в реальном времени. Текстовые промпты типа «увеличь отступы» дают нестабильные результаты, потому что ИИ интерпретирует «увеличь» субъективно. Слайдеры обеспечивают точное и повторяемое управление.

**Источник:** [Introducing Claude Design by Anthropic Labs](https://www.anthropic.com/news/claude-design-anthropic-labs)

**Дата:** 2026-05-08
