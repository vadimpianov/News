## 1. Компоненты & Паттерны

- **Принцип:** AI-инструменты для генерации UI дают кратно лучший результат при наличии формализованной дизайн-системы (токены, компоненты, переменные), чем при работе «с чистого листа».
- **Почему:** Reddit-дискуссия показала полярный разрыв: один и тот же инструмент (Claude Design) даёт «слоп» без дизайн-системы и «отличный результат» с ней — потому что AI может опираться на конкретные токены и правила, а не угадывать стиль.
- **Источник:** [The Neuron Daily — Reddit has thoughts](https://www.theneurondaily.com/p/anthropic-s-claude-design-launched-and-reddit-has-thoughts)
- **Дата:** 2026-05-07

## 2. Figma-техники

- **Принцип:** Двусторонний workflow «Code ↔ Canvas» (захват работающего UI → редактируемые фреймы в Figma → push изменений обратно в код) устраняет разрыв между дизайном и имплементацией эффективнее, чем однонаправленный хендофф.
- **Почему:** Традиционный хендофф — однонаправленный (дизайн → код), что создаёт drift. Двусторонний воркфлоу позволяет обоим направлениям (код → Figma, Figma → код) работать как единая система, сокращая «последнюю милю» и обеспечивая актуальность дизайн-артефактов.
- **Источник:** [Figma Blog — From Claude Code to Figma](https://www.figma.com/blog/introducing-claude-code-to-figma/)
- **Дата:** 2026-05-07

## 3. Компоненты & Паттерны

- **Принцип:** Дизайн-знания можно формализовать как структурированные markdown-скиллы (фреймворки, чеклисты, правила), которые AI-агент использует для выполнения задач по методологии дизайнера, а не по своему усмотрению.
- **Почему:** 63 скилла Marie Claire Dean показывают, что контроль над «как AI дизайнит» важнее, чем контроль над «что он генерирует». Кодификация экспертизы в markdown даёт воспроизводимость и масштабируемость дизайн-процесса без потери качества.
- **Источник:** [Marie Claire Dean — I Built 63 Design Skills For Claude](https://marieclairedean.substack.com/p/i-built-63-design-skills-for-claude)
- **Дата:** 2026-05-07
