# Предложенные дизайн-принципы (на одобрение)

Дата извлечения: 5 мая 2026

---

## 1. Компоненты & Паттерны

- **Принцип:** Каждый компонент в дизайн-системе должен содержать описание (description) с контекстом использования, ограничениями и вариантами — это критично не только для людей, но и для AI-агентов, которые читают эти описания через MCP.
- **Почему:** Figma MCP передаёт descriptions компонентов как контекст агенту — чем точнее описание, тем точнее генерация; без описания агент «угадывает» и производит generic output.
- **Источник:** https://www.creativebloq.com/ai/designing-using-claude-code-and-figma-mcp-how-good-are-they
- **Дата:** 2026-05-05

---

## 2. Figma-техники

- **Принцип:** Структура именования слоёв и организация вариантов в Figma-компонентах должна следовать предсказуемому паттерну (Category/Type/State), чтобы автоматизированные инструменты могли парсить и генерировать компоненты без ручного маппинга.
- **Почему:** При использовании Claude Code в Agentic Mode для манипуляции Figma-холстом через терминал, предсказуемая структура слоёв позволяет агенту корректно создавать и модифицировать компоненты; хаотичное именование приводит к дублям и ошибкам.
- **Источник:** https://medium.com/design-bootcamp/claude-code-figma-a-designer-developer-workflow-that-actually-works-b7d7545edc40
- **Дата:** 2026-05-05

---

## 3. Анти-паттерны

- **Принцип:** Не полагайся на AI-генерацию UI без привязки к конкретным дизайн-токенам (цвета, типографика, spacing) — результат будет выглядеть «generic» и узнаваемо-AI-шным.
- **Почему:** Claude Skills с привязанными токенами из реальной дизайн-системы производят UI, неотличимый от ручной работы; без токенов AI использует свои «дефолтные» представления о хорошем дизайне, которые однотипны для всех пользователей.
- **Источник:** https://www.hexabase.com/column/ai-design-claude-skills-workflow
- **Дата:** 2026-05-05
