## 1. Компоненты & Паттерны

- **Принцип:** Если ваша дизайн-система не учитывает shadcn/ui, AI-инструменты всё равно будут генерировать его паттерны — 114K+ звёзд на GitHub сделали его де-факто стандартом для AI-генерации.
- **Почему:** Claude, Copilot и другие AI-кодогенераторы обучены на огромном количестве shadcn/ui кода; ваши прототипы будут невольно повторять его компонентные паттерны (Radix + Tailwind), и лучше осознанно интегрировать или дифференцировать свою систему.
- **Источник:** [Pawel Klasa — The most important Design System in 2026](https://medium.com/design-bootcamp/the-most-important-design-system-in-2026-that-designers-missed-was-built-by-a-developer-d5617753882e)
- **Дата:** 2026-05-16

## 2. Figma-техники

- **Принцип:** При работе с Claude Code + Figma MCP необходимо создать "Harness" — набор из 4 Skills-ограничений (токены, компоненты, layout, стили), чтобы AI использовал существующую библиотеку, а не генерировал hex-коды и новые компоненты.
- **Почему:** Без явных constraint-правил Claude генерирует визуально корректный, но системно несовместимый результат — hex вместо токенов, кастомные компоненты вместо библиотечных, нарушая консистентность дизайн-системы.
- **Источник:** [Sen Lin — How to make Claude Code follow your design system in Figma](https://uxdesign.cc/how-to-make-claude-code-follow-your-design-system-in-figma-559618cffaa9)
- **Дата:** 2026-05-16

## 3. Анти-паттерны

- **Принцип:** "Claude Design ИЛИ Figma" — ложная дилемма; оптимальный воркфлоу использует Claude Design для идеации и первого черновика, а Figma — для коллаборации, handoff и экосистемной глубины.
- **Почему:** Попытка полностью заменить один инструмент другим приводит к потерям: Claude Design не поддерживает дизайн-систему для сотен разработчиков и не аргументирует UX-решения перед стейкхолдерами; Figma не генерирует концепты за минуты.
- **Источник:** [Lenny's Newsletter — What Claude Design is actually good for](https://www.lennysnewsletter.com/p/what-claude-design-is-actually-good)
- **Дата:** 2026-05-16
