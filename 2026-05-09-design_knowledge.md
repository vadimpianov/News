## 1. Figma-техники

- **Принцип:** Figma — место для формализации валидированного направления, а не для хранения каждого AI-черновика.
- **Почему:** Преждевременный перенос нестабилизированных паттернов в Figma засоряет канвас и создаёт иллюзию зрелости дизайна; сначала паттерны должны пройти итерации в прототипе (HTML/код), и только после стабилизации формализоваться в Figma.
- **Источник:** https://medium.com/@krismapp/how-im-using-claude-to-prep-for-handoff-8d287ded4aa8
- **Дата:** 2026-05-09

## 2. Компоненты & Паттерны

- **Принцип:** При работе с AI-генерацией дизайна — задавай дизайн-систему (цвета, типографика, spacing, компоненты) до генерации экранов, а не после.
- **Почему:** Без заданной системы AI угадывает визуальный язык каждый раз заново, что приводит к несогласованным палитрам, «усреднённым» лейаутам и лишним итерациям; предварительная настройка системы обеспечивает консистентность с первого результата.
- **Источник:** https://quasa.io/media/claude-design-looks-great-but-it-devours-your-token-limits-here-s-how-to-use-it-smartly
- **Дата:** 2026-05-09

## 3. Spacing & Layout

- **Принцип:** Выравнивай Figma-переменные с CSS-токенами, чтобы все инструменты (дизайн и код) говорили на одном языке spacing и цветов.
- **Почему:** Рассинхрон между Figma variables и CSS custom properties приводит к потерям при хэндоффе — AI-инструменты (Claude Code, Codex) генерируют hardcoded значения вместо токенов; единый source of truth для spacing и цветов устраняет drift между дизайном и кодом.
- **Источник:** https://uxdesign.cc/designing-with-claude-code-and-codex-cli-building-ai-driven-workflows-powered-by-code-connect-ui-f10c136ec11f
- **Дата:** 2026-05-09
