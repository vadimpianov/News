# Предложенные дизайн-принципы — 2026-10-23

## 1. Figma-техники

- **Принцип:** Используйте файл DESIGN.md (бренд-цвета, шрифты, spacing-правила, компоненты) как входной контекст для AI-генерации — это сокращает промпты на 40-60% и повышает консистентность результатов.
- **Почему:** Без зафиксированного бренд-контракта каждый промпт требует повторного описания стиля, а результаты расходятся между сессиями. DESIGN.md действует как design token manifest для AI.
- **Источник:** [Claude Designの使い方 — AI Agent Navi](https://aiagent-navi.com/?p=10112), [Zenn.dev — Claude Design解説](https://zenn.dev/tech_realinvent/articles/8476deca982896)
- **Дата:** 2026-10-23

---

## 2. Компоненты & Паттерны

- **Принцип:** При AI-прототипировании фиксируйте дизайн-токены ДО начала генерации компонентов — иначе каждая итерация создаёт дрейф стиля, который дорого исправлять.
- **Почему:** AI-генерация без locked-in токенов приводит к «творческому дрейфу»: каждый новый компонент немного отличается по spacing, border-radius, shadow. Фиксация токенов первым шагом делает все последующие итерации стилистически консистентными.
- **Источник:** [Claude Design Guide 2026 — StarAgile](https://staragile.com/blog/claude-design-guide), [Anthropic — Claude Design admin guide](https://support.claude.com/en/articles/14604406-claude-design-admin-guide-for-team-and-enterprise-plans)
- **Дата:** 2026-10-23

---

## 3. Анти-паттерны

- **Принцип:** Не используйте AI для полной перегенерации экрана при мелких правках — вместо этого делайте точечные изменения в существующем прототипе (Claude Code позволяет это, Figma Make — нет).
- **Почему:** Перегенерация ломает уже согласованные элементы и создаёт ненужный цикл ревью. Команда GitLab обнаружила, что точечные правки в Claude Code экономят до 50% времени итерации по сравнению с Figma Make.
- **Источник:** [GitLab Design — Claude Project Issue](https://gitlab.com/gitlab-org/gitlab-services/design.gitlab.com/-/issues/3209)
- **Дата:** 2026-10-23
