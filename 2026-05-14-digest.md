### Как заставить Claude Code следовать вашей дизайн-системе в Figma
**[How to make Claude Code follow your design system in Figma](https://uxdesign.cc/how-to-make-claude-code-follow-your-design-system-in-figma-559618cffaa9)** — Sen Lin, UX Collective, май 2026

**Суть:** ⭐ **Ключевая статья.** Claude Code через Figma MCP умеет писать напрямую в канвас Figma. Но проблема: он подставляет захардкоженные hex-цвета вместо дизайн-токенов, сырые числа вместо типографических токенов, создаёт одноразовые компоненты вместо библиотечных. Решение автора — концепция «Harness» (фреймворк ограничений). Создано 4 Claude Code Skill'а для Figma: первый генерирует Token Map и Component Registry как базовый чеклист перед началом сессии. Пока «Preflight» не пройден, ни один нод не создаётся. Это предотвращает ситуацию, когда через 30 минут работы обнаруживается, что токены библиотеки не загрузились.

## Выводы

### Какие приёмы можно применить в работе дизайнера

1. **Preflight-чеклист перед работой с Figma MCP.** Прежде чем Claude Code начнёт создавать ноды в Figma, запустите скилл, который генерирует Token Map и Component Registry. Это предотвращает захардкоженные значения вместо токенов. (Из статьи Sen Lin)

2. **design.md как исполняемый бренд-гайд.** Держите design.md отдельно от CLAUDE.md. В нём: дизайн-токены, type scale, spacing, компоненты. Claude Code будет применять эти правила автоматически, не инферя их заново каждый раз. (Из статей Kaho Ohara и picks design)

3. **Claude Design → Claude Code, а не наоборот.** Используйте Claude Design для быстрой генерации первого варианта, затем Handoff to Claude Code для продакшена. Не задерживайтесь в Claude Design — токены расходуются быстро. (Из статей Xinran Ma и Quasa.io)

4. **Комментарии > длинные промпты.** В Claude Design указывайте на конкретный элемент и оставляйте короткий комментарий вместо описания правок текстом. Точнее, быстрее, экономит токены. (Из Quasa.io)

5. ⭐ **ЗАПОМНИТЬ: концепция Harness для AI-дизайна.** Фреймворк ограничений вокруг модели (Token Map → Component Registry → Preflight → Production) — структурированный подход к тому, чтобы AI не «изобретал» свою дизайн-систему, а строго следовал существующей. Это применимо не только к Figma, но к любому AI-воркфлоу с дизайн-системами. Почему важно: без Harness каждый AI-сеанс начинается с чистого листа, и результат непредсказуем. (Из статьи Sen Lin, UX Collective)
